# App access and onboarding changes

## Release order

1. Deploy the backend changes first, including the authenticated `GET/POST /api/onboarding/waiver` endpoints.
2. Run `php artisan migrate --path=database/migrations/2026_10_27_000001_create_waiver_acceptances_table.php` against the intended deployment database. The development session did not run production migrations.
3. Place Dina's approved waiver as UTF-8 plain text at `storage/app/onboarding/waiver.txt`, or set `ONBOARDING_WAIVER_PATH` to its absolute path. No substitute legal wording is included. Until a nonempty document exists, the waiver is disabled. Publish it only after the acceptance-table migration is applied.
4. Release the updated mobile app. Authenticated startup destinations check the waiver before consultation. A changed document requires a new signature; the original text, signer name, version hash and acceptance time are retained.

## Changes and checks

- Subscription startup, status and access middleware recognize verified store purchases independently of the legacy account flag and check expiration. The app refreshes access before leaving successful checkout, blocks purchasing the currently active product, and retries the selected program after checkout.
- Master routines keep approved/legacy publication rules and exercise requirements, but use original text if a requested translation is unavailable. Local inspection found the full-body warm-ups tagged correctly but authored with `language=no`.
- Routine filters open on the root navigator, isolate their selection from the home tab, expose reset/change controls on empty results, and search titles, codes and tag names. Fresh loads and request sequencing prevent outdated filter responses from winning.
- Full program descriptions are visible before selection. Consultation choice answers become client tags; existing coach-assigned tags are preserved.
- Backend regression tests use an isolated in-memory SQLite database, never application data.
